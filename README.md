# Blue Stone Import

ระบบคุมการตัดเงินและบันทึกปูนเข้า ของ **BLUE STONE TRADING CO., LTD.** (จ.พะเยา)
นำเข้าปูนจากโรงงานฝั่งลาวผ่านด่านเชียงของ ส่งต่อให้ผู้ซื้อฝั่งไทย

เป็นเว็บไฟล์คงที่ล้วน ไม่มี build step ไม่มี backend ของตัวเอง
ข้อมูลเก็บในเบราว์เซอร์ของแต่ละเครื่อง และซิงก์ขึ้นฐานข้อมูล Supabase ให้ทุกเครื่องเห็นชุดเดียวกัน

เว็บจริง https://bluestone-import.vercel.app

## หน้าจอในระบบ

| ไฟล์ | ใช้ที่ไหน | ทำอะไร |
|---|---|---|
| `index.html` | ออฟฟิศ | ตัวระบบทั้งหมด 5 หน้า — คุมการตัดเงิน · บันทึกปูนเข้า · ค่าชิปปิ้ง · ตั้งค่าอัตรา · ส่งออกข้อมูล |
| `login.html` | ออฟฟิศ | เข้าสู่ระบบด้วยอีเมลหรือบัญชี Google และปุ่มติดตั้งเป็นแอป |
| `board.html` | จอทีวีในออฟฟิศ | จอแสดงคู่รถและปลายทางประจำวัน เลื่อนขึ้นวนเองอัตโนมัติ |
| `photos.html` | ออฟฟิศ | ดูรูปที่พนักงานขับรถส่งเข้ามา แยกตามงานและขั้นตอน |
| `d.html` | มือถือพนักงานขับรถ | ถ่ายรูปส่งกลับ เปิดจากลิงก์ที่ออฟฟิศส่งให้ ไม่ต้องล็อกอิน |

### index.html

- **คุมการตัดเงิน** เครดิตสองฝั่ง (เงินที่เราโอนไว้กับโรงงานฝั่งลาว และเครดิตที่ผู้ซื้อเหลืออยู่กับเรา) วงกลมสัดส่วนคงเหลือ ตารางเทียบว่าเหลือนำเข้าและส่งมอบได้อีกกี่ตันกี่คันรถ แยกปูนผงกับปูนถุง พร้อมสรุปรายเดือนและกำไรขั้นต้นโดยประมาณ
- **บันทึกปูนเข้า** จับคู่รถฝั่งลาวกับฝั่งไทยเป็นคู่ ๆ เก็บผู้ประกอบการ ทะเบียน ยี่ห้อปูน พนักงานขับรถ เบอร์โทร น้ำหนักชั่งได้ทั้งสองฝั่ง เวลารับปูนและเวลาออกจากโรงงาน และติ๊กผ่านเครื่องเอกซเรย์รายคู่
- **ลูกค้าปลายทาง** ทะเบียนลูกค้าพร้อมเลขประจำตัวผู้เสียภาษี ที่อยู่ไทยครบ **77 จังหวัด 928 อำเภอ 7,438 ตำบล** เติมรหัสไปรษณีย์ให้เอง และหมุดพิกัดที่ลากปรับตำแหน่งได้
- **ข้อความส่งงาน** สร้างข้อความถึงพนักงานขับรถ (แนบลิงก์ถ่ายรูป 3 ขั้นตอน) และข้อความแจ้งลูกค้า คัดลอกไปวางในแชตได้เลย
- **ค่าชิปปิ้ง** ฝั่งลาวคิดตามขั้นจำนวนรถ ฝั่งไทยคิดเหมาต่อคันหรือคิดตามน้ำหนัก
- **ส่งออกข้อมูลและรายงานวิเคราะห์** เลือกช่วงเวลา ชนิดปูน ลูกค้า จังหวัด และผู้ประกอบการ แล้วดูแดชบอร์ดสรุปบนจอ (ยอดนำเข้า ยอดขาย กำไรขั้นต้น กราฟรายเดือน ส่วนต่างน้ำหนัก ลูกค้า ปลายทาง กระแสเงินสด) หรือสั่งส่งออกเป็น Excel (.xlsx) · CSV · PDF (ผ่านหน้าต่างพิมพ์) · JSON เลือกได้ว่าจะเอาหัวข้อไหนบ้าง
- **ผู้ใช้งานและประวัติการแก้ไข** เพิ่มผู้ใช้ สลับผู้ใช้ที่กำลังทำงาน และบันทึกว่าใครแก้อะไรเมื่อไหร่

หน้าตั้งค่าอัตรามี 9 หัวข้อ: ชื่อคู่ค้าในระบบ · ราคาที่โรงงาน · ราคาขายให้ผู้ซื้อ · ขั้นราคาชิปปิ้งลาว · อัตราค่าชิปปิ้งไทย · ผู้ใช้งานและประวัติการแก้ไข · ฐานข้อมูลกลาง Supabase · ปิดงวดและเตือนเครดิต · รหัสชั้นที่ 2 ของหน้านี้

**รหัสชั้นที่ 2** หน้านี้ล็อกซ้อนอีกชั้นได้ด้วย PIN 6 หลักของผู้บริหาร ตั้งที่หัวข้อ 9 ตั้งแล้วเปิดหน้านี้ครั้งหน้าจะเจอจอใส่ PIN ก่อน ใครไม่รู้ PIN จะไม่เห็นและแก้ราคาไม่ได้ ใส่ผิดครบ 5 ครั้งหน่วง 15 นาที

ราคาปูนถุงเก็บเป็นบาทต่อตัน (1 ตัน = 20 ถุง) ช่องกรอกจะโชว์ราคาต่อถุงให้เทียบด้วย

**ปิดงวด** เมื่อกดปิดงวดถึงวันที่หนึ่ง รายการถึงวันนั้นจะถูกตรึงอัตราไว้กับตัวรายการเอง แก้อัตราวันนี้จะไม่กระทบยอดเก่าที่ส่งให้ใครไปแล้ว และรายการที่ตรึงแล้วบันทึกทับไม่ได้

### board.html

แสดงคู่รถของวันนี้ เลื่อนขึ้นทีละแถวทุก 6 วินาทีแล้ววนกลับ ดึงข้อมูลใหม่ทุก 1 นาที
สถานะ "ส่งถึงแล้ว" ยึดจากเวลาของรูปที่พนักงานขับรถส่งกลับเข้าระบบ ไม่ใช่การกดเอง

ขนาดตัวอักษรผูกกับความกว้างจอ จึงบอกขนาดจอให้ระบบรู้ครั้งเดียวแล้วมันจะจำไว้

```
board.html?tv=32    จอไม่เกิน 40 นิ้ว   แสดง 3 คัน ตัวใหญ่ เหลือเฉพาะข้อมูลหลัก
board.html?tv=43    41-50 นิ้ว         แสดง 4 คัน เพิ่มเวลารับปูนและที่อยู่ลูกค้า
board.html?tv=55    51-68 นิ้ว         แสดง 5 คัน ครบทุกช่อง (ค่าตั้งต้น)
board.html?tv=75    69 นิ้วขึ้นไป       แสดง 6 คัน ครบทุกช่อง
```

ตั้งแล้วเปิด `board.html` เฉย ๆ ครั้งต่อไปก็ยังใช้ค่าเดิม เพราะจำไว้ในเบราว์เซอร์เครื่องนั้น
ต้องบอกเองเพราะเบราว์เซอร์อ่านขนาดจอเป็นนิ้วไม่ได้ ทีวี 32 กับ 65 นิ้วรายงานกลับมาเป็น 1920×1080 เหมือนกัน

ต่อขึ้นจอด้วยมินิพีซีเปิด Chrome โหมด kiosk ได้ `chrome.exe --kiosk --app=https://bluestone-import.vercel.app/board.html?tv=43`
จอต้องล็อกอินครั้งแรกครั้งเดียว แล้วเครื่องนั้นจะจำสิทธิ์ไว้

### d.html — หน้าพนักงานขับรถ

ออฟฟิศกดสร้างข้อความส่งงาน จะได้ลิงก์ 3 ลิงก์ต่อหนึ่งคู่รถ แต่ละลิงก์มีโทเค็นสุ่ม 22 ตัวประจำงานนั้น

```
<เว็บ>/d.html?j=<รหัสงาน>&k=p&t=<โทเค็น>   รูปตอนรับปูนที่โรงงาน
<เว็บ>/d.html?j=<รหัสงาน>&k=b&t=<โทเค็น>   รูปใบชั่งและใบขนส่ง
<เว็บ>/d.html?j=<รหัสงาน>&k=d&t=<โทเค็น>   รูปตอนส่งปูนให้ลูกค้า
```

กดลิงก์แล้วเปิดกล้องในหน้าเว็บเลย ไม่ต้องลงแอปและไม่ต้องล็อกอิน ต้องเปิด GPS ก่อนจึงจะถ่ายได้
ระบบประทับวันเวลา พิกัด ชื่อสถานที่ รหัสงาน และทะเบียนรถ ลงบนภาพตั้งแต่ตอนถ่าย
ถ่ายได้สูงสุด **3 รูป** และวิดีโอ **1 คลิปไม่เกิน 20 วินาที** ต่อหนึ่งขั้นตอน

เลือกรูปจากคลังภาพก็ได้ แต่ระบบจะอ่าน EXIF ของไฟล์แล้ว **ติดธงแดง** บอกว่าไม่ได้ถ่ายผ่านระบบ
พร้อมบอกว่าไฟล์นั้นถ่ายเมื่อไหร่และมาจากกล้องรุ่นอะไร ออฟฟิศเห็นธงนี้ในหน้า `photos.html`

รูปที่เลือกจากคลังภาพจะถูกย่อให้ด้านยาว 1,600 จุดเท่ากับที่กล้องในระบบถ่าย (อ่าน EXIF จากไฟล์เดิมก่อนย่อ ธงแดงจึงยังทำงาน)
คลิปวิดีโอย่อในเครื่องไม่ได้ จึงจำกัดไว้ที่ 80 MB

## ตั้งค่า Supabase

รันสคริปต์ใน **SQL Editor → New query → Run** ตามลำดับนี้ รันซ้ำได้ไม่พัง

1. [`supabase/schema.sql`](supabase/schema.sql) — ตารางหลัก `app_settings` `entries` `customers` `app_users` `activity_log`
2. [`supabase/schema-photos.sql`](supabase/schema-photos.sql) — ตาราง `trip_photos` และถังเก็บไฟล์ `trip-photos`
3. [`supabase/schema-auth.sql`](supabase/schema-auth.sql) — ปิดสิทธิ์ของ anon เปลี่ยนเป็นเฉพาะผู้ล็อกอิน
4. [`supabase/schema-google.sql`](supabase/schema-google.sql) — บังคับว่าอีเมลที่ล็อกอินต้องมีอยู่ใน `app_users` ด้วย (จำเป็นเมื่อเปิดให้เข้าด้วยบัญชี Google)

แล้วเอา **Project URL** กับ **publishable key** (`sb_publishable_...` หรือ anon public key แบบเก่า) ใส่ใน [`config.js`](config.js)
หรือกรอกในเว็บที่หน้าตั้งค่าอัตรา หัวข้อ 7 **ห้ามใส่ `service_role` หรือ secret key เด็ดขาด**

เมื่อเชื่อมต่อแล้ว ทุกครั้งที่บันทึกข้อมูลระบบจะส่งขึ้นฐานข้อมูลให้เองภายใน 1.5 วินาที
และมีปุ่ม **ส่งข้อมูลขึ้น** / **ดึงข้อมูลลง** / **บันทึกทับ** ไว้สั่งเอง
ถ้ามีคนอื่นแก้ข้อมูลหลังจากเครื่องนี้ดึงล่าสุด ระบบจะไม่ส่งทับให้เอง ต้องกดบันทึกทับเอง

### สิทธิ์และการเข้าถึง

เมื่อรัน `schema-auth.sql` แล้ว ทุกตารางหลักเปิดให้เฉพาะผู้ที่ล็อกอิน (`authenticated`) เท่านั้น
ยกเว้นตาราง `trip_photos` ที่เปิดให้ `anon` เพิ่มแถวได้อย่างเดียว เพราะพนักงานขับรถส่งรูปโดยไม่ล็อกอิน
ถังเก็บไฟล์ `trip-photos` ตั้งเป็น private ออฟฟิศดูรูปผ่าน signed URL ที่หมดอายุเอง

publishable key เป็นคีย์ฝั่งผู้ใช้ เปิดเผยได้ตามปกติของ Supabase ด่านกันคนนอกจริง ๆ คือ Row Level Security ชุดนี้

**เพิ่มผู้ใช้** ที่ Supabase → Authentication → Users → Add user กรอกอีเมลกับรหัสผ่านให้พนักงานแต่ละคน
ควรปิด **Allow new users to sign up** ไว้ที่ Authentication → Providers → Email เพื่อไม่ให้คนนอกสมัครเองได้

### เข้าสู่ระบบด้วยบัญชี Google

หน้าล็อกอินมีปุ่ม **เข้าสู่ระบบด้วยบัญชี Google** อยู่แล้ว แต่จะใช้ได้ต่อเมื่อตั้งค่าครบ 3 อย่างนี้

1. **Google Cloud Console** → OAuth consent screen (External) ตั้งชื่อแอปและอีเมลติดต่อ
   → Credentials → Create OAuth client ID → Web application
   - Authorized JavaScript origins: `https://bluestone-import.vercel.app`
   - Authorized redirect URIs: `https://eoirzsvknmnjgsuvwzjz.supabase.co/auth/v1/callback` (เปลี่ยนตาม Project URL ใน `config.js` ถ้าย้ายโปรเจกต์)
2. **Supabase** → Authentication → Providers → Google → เปิด แล้ววาง Client ID กับ Client secret
3. รัน [`supabase/schema-google.sql`](supabase/schema-google.sql) ใน SQL Editor
   **ตรวจก่อนว่าอีเมลตัวเองอยู่ในตาราง `app_users` แล้ว ไม่อย่างนั้นจะล็อกตัวเองออก**

ข้อ 3 ห้ามข้าม ถ้าเปิด Google แล้วปล่อยนโยบายเดิมที่เขียนว่า "ผู้ล็อกอินทำได้ทุกอย่าง"
เท่ากับเปิดข้อมูลเงินของบริษัทให้ทุกคนที่มีบัญชี Google
หน้าเว็บเช็กซ้ำให้อีกชั้นและเด้งออกทันทีถ้าอีเมลไม่อยู่ใน `app_users`
แต่ชั้นที่กันได้จริงคือ Row Level Security ในไฟล์นั้น เพราะคนที่รู้วิธียิง API ตรงจะข้ามหน้าเว็บไปเลย

ถ้าปิด **Allow new users to sign up** ไว้ บัญชี Google ที่ยังไม่เคยมีใน Authentication → Users
อาจเข้าไม่ได้ ต้องสร้างผู้ใช้ไว้ก่อนหรือเปิด sign up แล้วให้ RLS ชุดนี้กันแทน

ปุ่ม Google ในหน้าล็อกอินยังใช้ตัวอักษร G แทนโลโก้จริง
ถ้าจะใช้งานจริงตามเงื่อนไขของ Google ต้องเปลี่ยนเป็นไฟล์โลโก้จากหน้า branding ของเขา

### การล็อกภายในเว็บ

**ล็อกหัวข้อฐานข้อมูล** หัวข้อ 7 ในหน้าตั้งค่าอัตราตั้งรหัสล็อกได้ คนที่ไม่รู้รหัสจะไม่เห็นค่าเชื่อมต่อและไม่มีปุ่มบันทึกทับ
เก็บเฉพาะค่าแฮช SHA-256 ของรหัส ไม่ได้เก็บตัวรหัส และซิงก์ให้ทุกเครื่องเมื่อส่งข้อมูลขึ้น
ลืมรหัสให้ลบคีย์ `lkH` กับ `lkS` ออกจากช่อง `rates` ของแถว `default` ในตาราง `app_settings` แล้วกดดึงข้อมูลลง
**รหัสชั้นที่ 2 ของหน้าอัตรา** หัวข้อ 9 ตั้ง PIN 6 หลักไว้ให้ผู้บริหารถือ ตั้งแล้วทั้งหน้าจะถาม PIN ก่อนเปิด
เก็บเป็นค่าแฮช SHA-256 + salt ในคีย์ `pnH` กับ `pnS` ซิงก์เหมือนกัน
ลืม PIN ให้ลบสองคีย์นั้นออกจากช่อง `rates` แถว `default` แล้วกดดึงข้อมูลลง

ช่องบทบาทในโปรไฟล์ผู้ใช้เลือกเองได้ จึงกันอะไรไม่ได้จริง ตัวที่กันคือ PIN นี้

การล็อกทั้งสองแบบนี้กันการกดแก้โดยไม่ตั้งใจและกันคนในที่ไม่เกี่ยวข้อง ไม่ใช่ระบบความปลอดภัยเต็มรูปแบบ
คนที่เปิดเครื่องมือพัฒนาของเบราว์เซอร์ยังอ่านค่าที่เก็บในเครื่องได้

## Deploy

ต่อ repo นี้เข้า Vercel ครั้งเดียว จากนั้น push ขึ้น GitHub เมื่อไหร่ Vercel จะสร้างเว็บใหม่ให้เอง

1. Import repo เข้า Vercel
2. Framework Preset เลือก **Other** ไม่ต้องตั้ง build command เพราะเป็นไฟล์คงที่
3. Output directory ปล่อยว่าง ใช้ root
4. ตั้งชื่อโปรเจกต์เป็น `bluestone-import` จะได้ `https://bluestone-import.vercel.app`

ถ้าเปลี่ยนชื่อเว็บบน Vercel ต้องแก้ `site` ใน `config.js` ให้ตรงด้วย เพราะใช้สร้างลิงก์ส่งรูปให้พนักงานขับรถ

บนเครื่องที่ทำงานอยู่ ดับเบิลคลิก [`push.bat`](push.bat) ครั้งเดียวจะ commit และ push ให้ทั้งหมด
ขั้นตอนละเอียดอยู่ใน [`PUSH.txt`](PUSH.txt)

## ติดตั้งเป็นแอปบนเครื่อง

- **Android / Chrome** กดปุ่ม "ติดตั้งเป็นแอปบนเครื่องนี้" ที่หน้าล็อกอิน หรือเมนูเบราว์เซอร์ → ติดตั้งแอป
- **iPhone / Safari** กดแชร์ → เพิ่มไปยังหน้าจอโฮม
- **คอมพิวเตอร์ / Chrome, Edge** กดไอคอนติดตั้งที่แถบที่อยู่

ไอคอนเป็นโลโก้บนพื้นขาว ล้อมด้วยวงแหวนสีม่วง `#5A4FD6` ให้เข้าชุดกับสีของระบบและแยกออกจากแอปเว็บหลัก
หน้าเข้าสู่ระบบใช้วงม่วงวงเดียวกันรอบโลโก้ เป็นเอกลักษณ์ที่แยกเว็บนี้ออกจากเว็บหลัก
`sw.js` ขอจากเน็ตก่อนเสมอ ได้ไฟล์ใหม่แล้วค่อยเก็บสำรองไว้ เปิดใช้งานต่อได้ตอนสัญญาณขาด และไม่ค้างไฟล์เก่าหลัง deploy
ข้อมูลจาก Supabase ไม่ถูกแคช ดึงสดเสมอ

บนมือถือ `index.html` กับ `photos.html` ตั้ง viewport ไว้ที่ 1180 จุด คือเรนเดอร์เป็นหน้าเว็บเต็มแล้วย่อให้พอดีจอ
ซูมสองนิ้วอ่านได้ ส่วน `d.html` `board.html` `login.html` ยังเป็นมุมมองมือถือปกติ

## โครงสร้างไฟล์

```
index.html                    ตัวระบบทั้งหมด รวม CSS, JS, ข้อมูลที่อยู่ไทย และโลโก้ ไว้ในไฟล์เดียว
login.html                    หน้าเข้าสู่ระบบ อีเมลหรือบัญชี Google ต่อกับ Supabase Auth
board.html                    จอคู่รถและปลายทาง สำหรับต่อทีวี
photos.html                   หน้าดูรูปจากพนักงานขับรถ ฝั่งออฟฟิศ
d.html                        หน้าถ่ายรูปของพนักงานขับรถ เปิดจากลิงก์
config.js                     Project URL, publishable key และที่อยู่เว็บจริง
manifest.webmanifest          ข้อมูลแอปสำหรับติดตั้งลงเครื่อง
sw.js                         service worker ขอจากเน็ตก่อน สำรองไว้ใช้ตอนออฟไลน์
icons/                        ไอคอนแอป 192, 512, maskable และ apple-touch
supabase/schema.sql           ตารางหลัก
supabase/schema-photos.sql    ตารางรูปและถังเก็บไฟล์
supabase/schema-auth.sql      ปิดสิทธิ์ anon เหลือเฉพาะผู้ล็อกอิน
supabase/schema-google.sql    บังคับว่าอีเมลที่ล็อกอินต้องอยู่ใน app_users (ใช้คู่กับการเข้าด้วย Google)
vercel.json                   ตั้งค่า deploy แบบไฟล์คงที่
push.bat                      ดับเบิลคลิกเพื่อ commit และ push ขึ้น GitHub
PUSH.txt                      ขั้นตอนการอัปขึ้นเว็บแบบละเอียด
```
